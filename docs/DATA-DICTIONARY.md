# 舱单数据定义

id是主单、分组单或箱货明细唯一字符串编号，parent为空表示主单。节点申报件数、净重和毛重是其完整子树的申报总量，校验时只加直接子节点，避免多层重复计数。包装carton=1件，pallet=10件；重量kg与t统一为kg。件数必须非负整数，净重非负且毛重不得低于净重。
拆并结构采用每节点最多一个父级的有向图；自环、长环、缺父级均阻断封存，保留环路径。不会以平面求和替代逐层校验。
危险品按明确分类与UN编号检查，3类与5.1类禁止同箱；未知分类和缺失编号需复核。此演示规则只覆盖文中三类，不替代运输合规审批。
报关总量只汇总主单，与context.json内的申报件数、净重和毛重逐项比较。重复同值折叠，重复编号冲突全部隔离。原始计数=采纳+隔离+空行+重复表头+重复同值行。
封存需所有图、重量、危险品和采信问题处理完毕。数值均Decimal，对外字符串保留精度，编号不转整数。
# 计费重量交接（M7，位于报关对账与版本封存之间）
船公司按主单申报毛重结算运费，港口以包装换算后逐层可核验的子层重量为核验依据。合同基准由 context.billing_basis 决定：verified=按可核验重量结算，declared=按申报毛重结算，可用 overrides 或顶层 billing_basis 覆盖。
可核验重量自底向上求子层合计；补正节点（含非叶子）以显式补正值为准再向上汇总，依赖环节点回退原申报。补正只写入 state.billing.corrections 与版本台账，records、weight_checks 与输入快照永不改写，原申报依据始终可追溯。
逐张主单凭证含计费基准（VERIFIED_GROSS/DECLARED_GROSS/DECLARED_GROSS_PENDING）、申报净毛重、可核验净毛重、毛重差异、计费重量、结算结论、阻断凭据、凭证版次与可否封存。子树存在图错误、逐层重量差异、采信隔离或危险品未闭合时凭证 SUSPENDED 且不能封存；verified 基准下证据未闭合暂按申报毛重挂账，declared 基准下差异仅挂账。申报对账未闭合时批次同样不能封存。
补正经 POST /api/runs/{run_id}/corrections 登记，按 request_id 幂等：同批重试沿用原凭证，不新增台账与版次；切换前保存上一版快照，构建失败或 POST /billing/rollback 回滚到上一版。受影响主单凭证版次+1，对账与封存结论（含封存哈希）同步重出。
